# P4 / 版本系统下载链路与大包分发

> 目标：理解游戏/客户端版本管理系统（以 P4 为原型）的部署与下载链路，以及大包（GB 级）分发平台的构建思路。

## 1. 链路全景

```text
构建/打包
  → 产物仓库（对象存储 / 文件服务器）
  → 版本元数据（版本号、清单、哈希、增量包）
  → 内网 CDN（分级缓存 + 调度）
  → 客户端下载（断点续传 / 分片 / 校验）
```

## 2. 版本管理与元数据

- **版本号规范**：主版本.次版本.构建号（如 1.4.0.20260808），保证可排序、可追溯。
- **清单文件（Manifest）**：文件列表 + 每文件哈希 + 体积 + 版本；客户端先拉清单再拉文件。
- **全量包与增量包**：增量生成算法（BSDiff/HDiff 或按文件粒度差异），降低下载量。
- **产物不可变原则**：同版本号文件内容不可变，URL 带版本号，支持长缓存。

## 3. 大包下载链路设计

### 3.1 断点续传

- 基于 HTTP Range；服务器必须正确处理 206 与 `Content-Range`。
- 客户端记录已下载分片，断线后从断点继续。
- **注意**：CDN 节点对 Range 请求的缓存支持要验证，避免「返回 200 全量」导致续传失效。

### 3.2 分片并发

- 将大文件按固定大小分片（如 4-8MB），客户端多线程并发下载后合并。
- 每片独立校验（MD5/SHA256），失败仅重下该片。
- 分片数上限控制，避免单用户打满节点带宽（配合限速）。

### 3.3 完整性校验

- 下载完成后校验整体哈希，失败触发整包重下或按分片重下。
- 服务端提供文件哈希接口，客户端可对比。

### 3.4 限速与保护

- 单连接限速（如 2-5MB/s），防止单用户占用过高带宽。
- 客户端并发数控制（如 4-8）。
- 节点级带宽保护：超阈值时降速/排队，而不是直接拒绝。

## 4. 发布流程

1. **构建**：CI 构建产物 → 上传产物仓库（带哈希与清单）。
2. **登记**：版本管理平台登记版本号、文件清单、灰度策略。
3. **预热**：大包文件提前预热到边缘节点（错峰、分批）。
4. **灰度**：先小范围用户（白名单/比例）验证下载与启动。
5. **全量**：逐步放量，监控下载成功率、回源量、源站负载。
6. **回滚**：切换版本号指向旧包 + 客户端强制/提示更新策略。

## 5. P4 服务部署与维护要点

如果涉及 P4（Perforce）服务本身的部署维护：

- **服务拓扑**：P4D 主服务器 + 副本（Replica）+ 代理（Proxy）；备份服务器（Checkpoint + Journal）。
- **备份**：定期 Checkpoint 与 Journal 归档；验证可恢复性（演练）。
- **性能**：P4 元数据（db.*）对磁盘 IO 敏感，使用 SSD/本地盘；大文件存储走 Depots。
- **故障处理**：服务异常时检查磁盘空间、锁文件、日志；恢复顺序（先副本后主）。
- **下载链路**：P4 客户端拉取大文件性能有限，生产常用「P4 同步 + 文件服务/CDN」双通道：元数据走 P4，大文件走 CDN。

## 6. 下载平台建设检查清单

- [ ] 元数据与文件分离存储，支持海量小文件与 GB 级大文件
- [ ] 清单接口高可用、可缓存
- [ ] 断点续传与分片并发协议完备（含 Range、Content-Range）
- [ ] 端到端校验（分片 + 整包）
- [ ] CDN 预热/刷新自动化（对接版本发布）
- [ ] 监控：下载成功率、平均/峰值速率、失败原因分布、回源量
- [ ] 灰度与回滚能力
- [ ] 源站与带宽容量规划
