# SLO 制定与容量规划

## 1. SLO / SLI / 错误预算

### 概念

- **SLI**：可量化的指标（如：下载请求成功率 = 成功请求数 / 总请求数）。
- **SLO**：目标值（如：下载成功率 99.9%）。
- **错误预算**：1 − SLO 的容忍空间（如 99.9% 对应每月 43 分钟不可用），用于决策发布与变更。

### 制定步骤

1. 明确用户可感知的核心路径（下载、登录、查询……）。
2. 为每个核心路径定义 SLI（成功率、延迟 P99、可用性）。
3. 定 SLO：基于现状基线 + 业务诉求，可接受（先 99% → 逐步 99.9%）。
4. 监控 SLI 与错误预算消耗，超出预算触发复盘与冻结发布。

### 示例

| SLI | SLO | 错误预算/月 |
| --- | --- | --- |
| 下载成功率 | 99.9% | ~43 分钟 |
| 下载首字节延迟 P95 | < 1s | - |
| 缓存命中率 | > 95% | - |

## 2. SLO 落地

- Prometheus 计算 SLI（`success_total / total`），Grafana 面板展示。
- 错误预算消耗告警：80% 消耗预警、100% 触发复盘。
- 发布门禁：错误预算不足时限制高风险变更。

## 3. 容量规划方法论

### 步骤

```text
1. 基线采集：近 3-6 个月峰值（带宽、QPS、并发、存储、连接数）
2. 增长预测：业务增速 × 季节性 + 事件性峰值（大版本发布、活动）
3. 资源测算：
   - 计算：QPS × 单请求资源成本
   - 带宽：并发下载数 × 平均速率
   - 存储：日增量 × 保留天数 × 副本
   - 连接：长连接数 + 峰值突发
4. 冗余策略：N+1 或 1.3-1.5 倍峰值
5. 输出报告：当前水位 / 预测 / 扩容清单 / 时间点 / 风险
6. 持续校准：每次活动后对比预测与实际
```

### 关键水位告警

| 资源 | 预警 | 危险 |
| --- | --- | --- |
| 磁盘 | 70% | 85% |
| 带宽 | 70% | 85% |
| CPU | 70%（长时间） | 85% |
| 内存 | 75% | 90% |
| 连接数 | 70% | 85% |

## 4. 容量与 SLO 联动

- 容量不足会直接冲击 SLI（延迟升高、成功率下降）。
- 建立「容量 → SLI」影响模型：如带宽 90% 时下载速度下降 X%，提前触发扩容。
- 大版本发布前做专项容量评估（预热、回源、下载并发）。
