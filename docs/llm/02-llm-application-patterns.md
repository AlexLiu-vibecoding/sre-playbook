# LLM 应用模式：Prompt、RAG、微调与工程落地

> 把 LLM 用于真实业务时的常见模式与选型思路。原则：**先简单后复杂**，能单次调用解决就不要上 RAG，能 RAG 解决就不要微调。

## 1. 技术选型：Prompt vs RAG vs 微调

| 方案 | 适用场景 | 优点 | 缺点 |
| --- | --- | --- | --- |
| Prompt 直接调用 | 通用任务、格式转换、摘要 | 简单、成本低、迭代快 | 不引入私有知识 |
| RAG | 需要最新/私有知识，可检索 | 知识可更新、可溯源、不改模型 | 依赖检索质量 |
| 微调 | 稳定改变输出风格/格式/领域语言 | 输出可控性强 | 数据成本高、易过拟合、需维护 |

决策顺序：先试 Prompt → 不够再上 RAG → 仍然不够（格式/风格问题）才考虑微调。

## 2. Prompt Engineering

### 结构化 Prompt

```text
角色：你是资深的 SRE 工程师。
任务：根据下面的错误信息给出排查步骤。
约束：
- 只基于提供的信息，不要臆测
- 输出格式：现象 / 可能原因 / 排查步骤
示例：
输入：... 输出：...
输入：{实际内容}
```

要点：

- **角色 + 任务 + 约束 + 示例**四件套。
- **Few-shot**：给 2-3 个高质量示例，比描述更有效。
- **CoT（思维链）**：要求「先分析再给结论」，复杂推理更稳。
- **结构化输出**：要求 JSON/XML 并用 schema 校验，别靠「格式好看」。
- 固定输入里用户内容用分隔符包裹，降低注入风险。

## 3. RAG（检索增强生成）

### 核心流程

```text
文档入库：切分 → 向量化 → 写入向量库
查询：问题向量化 → 检索 Top-K → 重排 → 拼入 prompt → 生成
```

### 各环节要点

| 环节 | 要点 |
| --- | --- |
| 切分（Chunking） | 按语义/标题/固定长度切；块太碎丢上下文，太大噪声多；重叠切分 |
| 向量化 | 选择 embedding 模型；领域语料可用领域模型 |
| 向量库 | FAISS、pgvector、Milvus、Qdrant、Chroma 等；注意规模与一致性 |
| 检索 | 向量检索 + 关键词检索（BM25）混合，互补 |
| 重排（Rerank） | 对 Top-K 用 rerank 模型精排，明显提升准确率 |
| 生成 | prompt 里给「只用检索内容作答 + 无法回答就明说 + 标注来源」 |

### RAG 质量排查

- 答非所问 → 检索没召回相关内容 → 查 chunk 质量与查询改写。
- 答得笼统 → Top-K 太少或重排没生效。
- 引用了不存在的来源 → 生成阶段未强制溯源，需加约束与校验。
- 检索慢 → 向量库规模/索引类型/并发问题。

## 4. 工具调用（Function Calling / Tool Use）

让模型调用外部工具（查询数据库、调 API、执行命令）：

```json
{
  "name": "query_metrics",
  "description": "查询 Prometheus 指标",
  "parameters": {
    "type": "object",
    "properties": {
      "query": { "type": "string", "description": "PromQL 表达式" }
    },
    "required": ["query"]
  }
}
```

工程要点：

- 工具描述要写清楚「什么时候用、参数含义、返回什么」。
- 返回结果要结构化；失败要有明确错误信息，供模型判断重试或换方案。
- 工具权限最小化：模型只拿到任务需要的工具。
- 记录每次工具调用（输入输出、耗时、成本）用于追溯。

## 5. 微调

### 什么时候需要

- 输出格式/风格有硬性要求，Prompt 怎么调都不稳。
- 领域术语、代码风格需要内化。
- 需要降低 prompt 长度/成本（把固定规则压进权重）。

### 实践要点

- 数据质量 > 数据量：几百到几千条高质量样本往往够。
- 用 LoRA 等参数高效微调，成本低、易回滚。
- 留出验证集，微调前后跑同一评估集对比，防止能力退化。
- 微调不能解决「知识不足」——知识问题交给 RAG。

## 6. 成本与性能工程

- **模型分级路由**：简单问题走小模型，复杂问题走大模型。
- **缓存**：相同/相似请求命中缓存（语义缓存）。
- **精简输入**：去掉无关上下文，控制 token 消耗。
- **批量与异步**：离线任务批量处理，摊薄成本。
- **预算控制**：给每次调用/任务设 token 上限与费用上限。

## 7. 安全与治理

- 输入输出过滤：内容审核、敏感词、PII 脱敏。
- 提示注入防护：用户输入与系统指令隔离；工具结果按不可信数据处理。
- 审计日志：记录 prompt、输出、模型、版本、成本。
- 上线前评估：黄金集 + 红队测试（越狱/注入/有害内容）。
- 版本管理：prompt 与模型版本入库，支持回滚。
