# On-call 值班 SOP

## 1. 值班目标

任何告警/故障在承诺时限内有人响应并止血；处理过程可追踪、可复盘。

## 2. 值班流程

```text
告警触发
  → 15 分钟内确认（认领）
  → 判断级别与影响面
  → 按 Runbook 止血
  → 无法解决时按升级路径升级
  → 恢复后记录时间线与处理过程
  → 交接与复盘
```

## 3. 响应规范

- 接到告警先在值班群确认认领，避免多人同时操作。
- 先止血后根因：恢复服务优先，根因分析放到恢复后。
- 涉及变更/高风险操作时呼叫二线，不独自执行未评审操作。
- 记录关键时间点（发现、定位、止血、恢复）。

## 4. 升级路径

| 等级 | 场景 | 升级 |
| --- | --- | --- |
| P0 | 核心业务全部不可用 | 立即拉群 + 呼叫二线/Owner + 值班经理 |
| P1 | 大范围/关键链路异常 | 15 分钟呼叫二线，30 分钟未解决升级 |
| P2 | 局部异常有绕过 | 正常工作时间处理，必要时升级 |
| P3 | 低影响 | 记录排期 |

## 5. 交接

每班交接内容：

- 未关闭告警及状态
- 进行中的变更/发布
- 遗留问题与注意事项
- 需要跟进的复盘项

## 6. 值班质量评估

- MTTA（响应）、MTTR（恢复）统计。
- 误报/漏报分析（每周）。
- 值班期间处理闭环率。
