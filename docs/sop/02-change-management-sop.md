# 变更管理 SOP

## 1. 目标

让每次变更可评审、可回滚、可追踪，把「变更」这一最高频故障来源纳入管控。

## 2. 变更分级与流程

| 级别 | 定义 | 流程 |
| --- | --- | --- |
| L1 低风险 | 监控配置、日志级别、非核心参数 | 记录即可，当日同步 |
| L2 中风险 | 常规组件升级、参数调整 | 评审 + 变更窗口 + 回滚预案 |
| L3 高风险 | 架构调整、核心链路发布、数据迁移 | 专项评审 + 演练 + 审批 + 双人复核 |

## 3. 变更单内容

```markdown
- 变更标题与背景
- 影响范围与业务
- 变更内容（命令/配置 diff）
- 风险评估与应对
- 回滚方案（必须）
- 执行窗口与步骤
- 验证标准（指标/功能）
- 干系人
```

## 4. 执行纪律

1. 变更窗口避开业务高峰（大版本发布提前预约窗口）。
2. 高风险变更双人复核（执行 + 监督）。
3. 分批执行，灰度验证，禁止一把梭。
4. 变更后 24-48h 观察期，指标对比基线。
5. 变更失败立即按回滚方案执行，不在故障中继续调试。

## 5. 变更复盘

- 每次线上事故先查最近变更清单。
- 月度变更统计：成功率、回滚率、引发的故障数。
- 高频失败类型沉淀为检查项。
