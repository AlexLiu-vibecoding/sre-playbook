# CDN 标准操作流程（SOP）

## SOP 1：大版本发布保障

### 前置检查（发布前 T-1 天）

- [ ] 发布文件清单确认：数量、体积、版本号、目录结构
- [ ] 源站容量确认：磁盘、带宽、对象存储配额
- [ ] CDN 缓存策略确认：新版本 URL 是否隔离（版本化路径）
- [ ] 预热计划：预热文件列表、批次、时间窗口、验证方式
- [ ] 回滚预案：旧版本路径可用性、刷新/切换脚本
- [ ] 监控与告警就绪：命中率、回源量、下载成功率、节点带宽
- [ ] 通知干系人：发布窗口、影响、应急联系人

### 发布执行

1. 按批次上传文件到源站（先小后大，观察源站负载）。
2. 分批提交预热任务，**错峰**执行，监控回源量曲线。
3. 预热验证：抽查节点文件存在性、大小、哈希一致。
4. 切换流量（域名/调度权重）→ 观察指标 15-30 分钟。
5. 发布确认：下载成功率、命中率、错误率回归基线。

### 发布后

- [ ] 一致性抽查：版本号、文件哈希
- [ ] 指标留存：发布前后对比报告
- [ ] 如异常：执行回滚（刷新新版本缓存、切换旧版本路径）

## SOP 2：容量规划

```text
每季度/大版本前执行：
1. 收集近 3 个月峰值数据（带宽、QPS、下载并发、回源量）
2. 预测下一周期峰值 = 历史峰值 × 业务增长系数 + 版本发布增量
3. 计算节点与带宽需求（含 30-50% 冗余）
4. 检查磁盘水位与缓存策略（命中率目标是否仍可达）
5. 输出容量报告：当前水位 / 预测需求 / 扩容清单 / 风险项
6. 扩容执行后回归验证，更新容量基线
```

## SOP 3：故障处置（Severity 分级）

| 级别 | 定义 | 响应时限 | 升级 |
| --- | --- | --- | --- |
| P0 | 全站下载不可用 | 立即 | 立即拉群、Owner 介入 |
| P1 | 大规模/核心链路异常 | 15 分钟 | 30 分钟未解决升级 |
| P2 | 局部异常、有绕过方案 | 30 分钟 | 当天解决 |
| P3 | 低影响 | 工作时间 | 排期处理 |

### 故障处置五步

1. **止血**：摘除异常节点/域名切备用/回滚 → 恢复服务优先。
2. **定位**：按排查手册逐段排除，建立时间线。
3. **根因**：直接原因 + 深层原因（为什么没有提前发现/拦截）。
4. **恢复确认**：指标回到基线、影响用户复测。
5. **复盘**：24-48h 内输出复盘报告。

### 复盘报告模板

```markdown
## 故障复盘
- 时间线（发现/定位/止血/恢复/根因）
- 影响面（用户、业务、指标）
- 直接原因
- 深层原因（监控缺失/变更无评审/容量不足/人为失误）
- 改进项（每个改进项含负责人与截止时间）
- 遗留风险
```

## SOP 4：日常巡检

每日：

- 节点健康检查结果
- 命中率 / 回源成功率 / 下载成功率曲线
- 带宽与磁盘水位（超过 70% 预警）
- 异常告警处理

每周：

- 容量水位周报
- 告警复盘（误报、漏报、重复告警治理）
- 发布与变更记录核对

每月：

- 容量规划更新
- 故障复盘回顾与改进项验收
- 演练计划（节点故障、源站故障、DNS 切换）
