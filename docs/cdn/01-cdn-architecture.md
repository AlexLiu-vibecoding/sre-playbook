# CDN 架构与核心原理

> 适用：内网 CDN / 大规模文件分发。本文回答「CDN 是什么、怎么搭、关键机制怎么设计」。

## 1. CDN 要解决什么问题

1. **就近访问**：用户从最近的边缘节点取内容，降低跨地域延迟与骨干网压力。
2. **源站保护**：大部分请求被边缘命中，回源量大幅下降。
3. **带宽扩容**：边缘节点分担出口带宽，支撑大包/高并发下载。
4. **稳定容灾**：节点级故障自动切换，DNS 调度摘除异常节点。

## 2. 整体架构

```text
用户/客户端
   │  (1) 域名解析
   ▼
DNS 调度（权威 DNS / 自建 DNS / HTTPDNS）
   │  (2) 返回最优边缘节点 IP
   ▼
边缘节点（LVS/Nginx → 本地缓存磁盘）
   │  (3) 未命中则回源
   ▼
二级/中心节点（大文件分级缓存）
   │
   ▼
源站（对象存储 OSS/S3 / 文件服务器 / 构建产物仓库）
```

**两级缓存（边缘 + 中心）** 是内网大文件分发的常见结构：边缘承担终端流量，中心合并回源压力。

## 3. 核心机制

### 3.1 缓存与命中

- **缓存键**：默认 URL；带查询参数的 URL 需明确是否参与缓存键（影响命中率与一致性）。
- **缓存策略**：由源站响应头（`Cache-Control: max-age`、`ETag`）或 CDN 规则决定。
- **大文件缓存**：按文件大小/版本号决定缓存时长；安装包类**不可变文件**可长缓存 + 版本化路径。
- **命中率目标**：文件分发场景追求 95%+；命中率低先查缓存键、Header、调度是否分散。

### 3.2 回源

- **回源协议**：HTTP/HTTPS；回源 Host 与 SNI 要匹配源站。
- **回源超时与重试**：连接超时、读超时、失败重试次数；避免重试风暴。
- **回源限流/熔断**：源站过载时，边缘节点要**降级**（如只回源热点文件）而不是无限重试打垮源站。
- **回源带宽评估**：峰值回源 = 峰值总流量 × (1 − 命中率)，据此规划源站带宽。

### 3.3 预热（Preload/Prewarm）

- **触发时机**：大版本发布前、大文件首次上线时，主动把内容推送到各边缘节点。
- **方式**：管理平台批量提交预热任务 → 各节点按列表回源并缓存。
- **注意**：预热本质是把回源流量提前；要分批、错峰，避免同时预热把所有源站打挂。
- **验证**：预热完成后抽查节点本地缓存文件是否存在、大小一致。

### 3.4 缓存一致性

**问题**：文件更新后，边缘节点仍返回旧版本。

**方案对比**：

| 方案 | 原理 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 版本化路径 | URL 带版本号/时间戳，新版本=新 URL | 简单可靠，天然一致 | 需要业务配合；老版本 URL 累积 |
| 主动刷新/失效 | 发布后调用 CDN API 批量刷新 URL/目录 | 精确、即时 | 刷新有延迟，未刷新前仍可能旧 |
| 短 TTL | 减小 max-age | 最终一致快 | 命中率下降 |
| 条件请求 | ETag/Last-Modified 回源校验 | 兼顾一致与命中 | 回源量增加 |

**生产建议**：不可变文件（安装包、构建产物）用「版本化路径 + 长缓存」；可变文件用「短 TTL + 主动刷新」。

### 3.5 DNS 调度

- **调度依据**：用户 IP 归属（地域/运营商）、节点负载、节点健康状态、业务优先级。
- **返回方式**：直接返回 IP 或返回 CNAME 由调度系统二次决策（支持灰度/应急切换）。
- **TTL 权衡**：TTL 长 → 调度稳定、生效慢；TTL 短 → 切换快、解析压力大。故障场景下配合**主动下线**而非等 TTL。
- **故障摘除**：节点健康检查失败 → 调度系统不再返回该节点；同时保留一个「兜底域名」便于应急。

## 4. 容量规划

```text
峰值流量 = 在线峰值人数 × 人均下载速率
节点带宽需求 = 峰值流量 / 节点数（预留 30%~50% 冗余）
磁盘需求 = 热点内容体积 × 冗余副本数
回源带宽 = 峰值流量 × (1 − 目标命中率)
```

要点：

- 按**并发下载数 × 单连接速率**估算，而不是只看平均带宽。
- 大包场景连接速率要限制（限速）来保护节点带宽与源站。
- 预留峰值余量 + 故障节点摘除后的重分配余量。

## 5. 发布保障

1. **发布前**：清单核对（文件数量、体积、版本）、预热、源站容量确认、回滚预案。
2. **发布中**：分批预热、观察回源量与源站负载、抽查节点命中。
3. **发布后**：一致性抽查（版本号/哈希）、指标对比（命中率、回源量、下载成功率）、异常回滚（刷新/切换旧版本）。

## 6. 稳定性设计清单

- [ ] 节点多地域冗余，单节点故障可自动摘除
- [ ] 源站多副本 + 自动切换（OSS/S3 跨区复制）
- [ ] 回源限流/熔断，防止源站雪崩
- [ ] 预热与刷新 API 完备，支持批量与异步
- [ ] 监控：命中率、回源量、回源成功率、下载成功率、节点负载、带宽
- [ ] 告警：指标异常 + 容量水位 + 节点健康
- [ ] 演练：节点故障演练、源站故障演练、大版本发布演练
